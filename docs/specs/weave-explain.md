# Specification: Weave Explain

## 1. Overview

`weave explain` exposes the scoring behind a search result. It answers:

- Which keywords matched?
- Which fields matched, and how strongly?
- What were the keyword, fuzzy and hybrid scores?
- Why did this document rank where it did?

```sh
weave explain <path> <query> [--id <id>] [--mode hybrid|keyword|fuzzy] [--top-k <n>] [--json]
```

## 2. Goals and Non-Goals

### Goals

- Make ranking inspectable and debuggable.
- Support calibration and editorial decisions.
- Explain both matched and non-matching documents.
- Return stable, schema-validated diagnostics.

### Non-Goals

- Changing ranking behavior.
- Natural-language explanations generated by an LLM.
- Cross-bundle comparison.
- Query rewriting suggestions.

## 3. Command Contract

```text
weave explain <path> <query> [--id <id>] [--mode hybrid|keyword|fuzzy] [--top-k <n>] [--json] [--no-cache]
```

- `--id` selects the concept to explain.
- Without `--id`, explain the rank-1 result in the selected mode.
- `--mode` defaults to `hybrid`.
- `--top-k` defaults to 10; valid `1..100`.
- Exit codes:
  - `0` — explanation produced.
  - `1` — no result to explain (`--id` not found and no matches, or empty query).
  - `2` — usage/invalid parameters.
  - `3` — permission denied.

## 4. Result Model

```json
{
  "query": "oauth tokn",
  "mode": "hybrid",
  "top_k": 10,
  "id": "concepts/oauth-token-rotation",
  "rank": 1,
  "found": true,
  "keyword": {
    "score": 0.75,
    "matched_keywords": ["oauth"],
    "tokens": [
      {
        "query_token": "oauth",
        "matched_keyword": "oauth",
        "match": "exact",
        "score": 1.0
      }
    ]
  },
  "fuzzy": {
    "score": 0.87,
    "matched_fields": ["title", "description", "body"],
    "fields": [
      {
        "field": "title",
        "score": 1.0,
        "weight": 1.0,
        "contribution": 0.526
      }
    ],
    "tokens": [
      {
        "query_token": "tokn",
        "matched_token": "token",
        "field": "title",
        "similarity": 0.89
      }
    ],
    "snippet": "…"
  },
  "hybrid": {
    "keyword_weight": 0.50,
    "fuzzy_weight": 0.50,
    "total": 0.81
  }
}
```

### Fields

- `rank` is 1-based in the selected mode’s top-K; `0` when the document is outside the top-K.
- `found` is true when the id exists in the bundle, even if it has no match.
- Component scores use the same rounding as `weave search`.
- `matched_keywords` are original keyword values.
- `tokens` lists per-query-token evidence.
- `fields` lists per-field fuzzy scores and weighted contributions.
- `snippet` is present only when the body contributes a match.

## 5. Scoring Semantics

The explanation must reuse the production scoring logic, not duplicate it:

- Keyword: exact `1.0`, prefix `0.75`, AND across query tokens.
- Fuzzy: max of normalized Levenshtein and trigram Dice; title `1.00`, description `0.60`,
  body `0.30`; normalized by `1.90`.
- Hybrid: `0.50 * keyword + 0.50 * fuzzy`.
- Field and fuzzy thresholds match the search spec.

If `--id` is outside the top-K, compute its scores directly but report `rank: 0`.
If the id is unknown, return `CONCEPT_NOT_FOUND` and exit `1`.

## 6. Human Output

```text
query: oauth tokn
mode: hybrid (top 10)
result: concepts/oauth-token-rotation  rank 1

keyword  0.750
  oauth  exact   1.000  → keyword "oauth"
  tokn   none    —      (no keyword match)

fuzzy    0.870
  title        1.000  weight 1.00  contribution 0.526
  description  0.900  weight 0.60  contribution 0.284
  body         0.400  weight 0.30  contribution 0.063
  token matches
    tokn → token  title  0.89

hybrid   0.810
  0.50 * 0.750 + 0.50 * 0.870
```

## 7. Determinism

- Token/field evidence sorts deterministically.
- Scores use four-decimal rounding.
- Output does not depend on map iteration order.

## 8. Testing

- Exact keyword, prefix and no-match token.
- Fuzzy typo explanation.
- Title vs description vs body contributions.
- `--id` inside and outside top-K.
- Unknown id and empty query.
- Hybrid, keyword and fuzzy modes.
- CLI envelope and human output.

## 9. Acceptance Criteria

- Explanation values match `weave search` scores exactly.
- Every score component is traceable to matched tokens/fields.
- Unknown ids produce `CONCEPT_NOT_FOUND`.
- `rank: 0` is used for known ids outside top-K.
- Output is stable and schema-validated.
